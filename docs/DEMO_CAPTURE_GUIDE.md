# 실제 제출 화면 캡처: 최소 5장

현재 시연 주소는 **이 PC에서만** 열리는 http://127.0.0.1:18084 입니다. 공개 배포 URL이 아닙니다. 전용 가상 DB와 샘플 20개만 사용하며 실제 계정/고객 자료는 입력하지 않습니다. 시연 계정 정보는 대화에서 전달된 로컬 전용 값을 사용하거나 Swagger에서 가상 회원을 직접 만드세요.

## 1. Jinja2 화면
`http://127.0.0.1:18084/`를 열어 상품·가격·재고·검색 필터가 보이게 캡처합니다. 상품 상세도 열어 깨지지 않는지 확인합니다. 이미지 이름 예: `01-jinja-catalog.png`.

## 2. Swagger UI
`http://127.0.0.1:18084/docs`에서 서비스 제목과 회원·인증·상품·주문·게시판 API가 보이게 캡처합니다. 이미지 이름 예: `02-swagger.png`.

## 3. 정상 200
Swagger의 `GET /v1/products` → Try it out → Execute. 응답 Code 200과 상품 JSON을 함께 캡처합니다. `03-products-200.png`.

## 4. 규칙 위반 400
먼저 Authorize 창의 **username에 이메일**, password에 시연용 비밀번호를 입력합니다. 창을 닫은 뒤 본인의 `PATCH /v1/users/{user_id}/password`를 실행합니다. user_id는 가상 회원가입 응답의 data.id입니다.
```json
{
  "old_password": "WrongPass1!",
  "new_password": "ChangedPass1!"
}
```
잘못된 기존 비밀번호로 인해 400이며 실제 비밀번호는 변경되지 않습니다. 응답 Code 400과 오류 JSON만 캡처합니다. `04-rule-400.png`.

재고 부족은 409, 입력 형식 오류는 422입니다. 다른 결과를 400으로 바꿔 적지 마세요. 없는 상품 `GET /v1/products/2147483647`의 404도 추가 캡처하면 좋습니다.

## 5. JWT 블랙리스트 401
인증된 상태에서 `POST /v1/auth/logout` → Execute로 204를 확인합니다. **Authorize에서 로그아웃하거나 새로 로그인하지 말고 같은 토큰을 그대로 둡니다.** 이어서 `GET /v1/orders` → Execute. 401 응답을 캡처합니다. `05-blacklist-401.png`.

## 제출 전에
- 토큰, 비밀번호 입력, Authorization 헤더/curl, DB 연결 문자열, 실제 개인정보가 화면에 없도록 응답 영역만 캡처합니다.
- 캡처는 docs/screenshots/에 두고 README에 실제 파일 링크를 추가합니다. 없는 이미지를 첨부 완료라고 쓰지 않습니다.
- 로컬 시연 서버가 켜져 있을 때만 URL이 열립니다. 작업을 마친 뒤 시연 서버를 종료합니다. 다시 실행할 때는 README의 환경변수·실행 안내를 따릅니다.
- 브라우저 직접 확인은 아직 미완료이며 이 안내 문서 자체는 캡처 증거가 아닙니다.
